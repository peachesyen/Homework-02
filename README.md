# PetEmotion AI — Final Project Video Reel Agent (HW2)

A [PydanticAI](https://ai.pydantic.dev/) agent that reads `project_proposal.md`
(the proposal for **PetEmotion AI**, my MGT 575 final project) and produces a
~30-60 second narrated video reel pitching it: a structured slide plan, HTML/CSS/SVG
slides, TTS narration, a critique-and-revise pass on every slide, and a
stitched `reel.mp4` — with slide generation, narration, and their enhancement
all running **in parallel** across slides.

- All LLM output uses **`gpt-5.6-luna`**.
- All TTS output uses **`tts-1-hd`** (Gemini TTS supported as an optional
  alternative — see below).

## Quickstart

```sh
python3 -m venv .venv && source .venv/bin/activate   # optional but recommended
pip install -r requirements.txt
python -m playwright install chromium                 # headless renderer for the slides

cp .env.example .env
# edit .env and set OPENAI_API_KEY (see "Running without an API key" below
# if you just want to see it work first)

python reel_agent.py
```

That's it — `reel_agent.py` reads `project_proposal.md` from the repo root
and writes everything else. On completion you'll have:

```
slides/slide_1.html ... slide_N.html   # final HTML slides (also embedded in reel.mp4)
ai_grading/slide_plan.json             # the slide plan (description + narration per slide)
ai_grading/critique_feedback.json      # per-slide critique + before/after revision
ai_grading/agent_flow.png              # agent pipeline diagram
build/reel.mp4                         # the stitched video (upload this to the grading site)
```

`build/` (rendered frames, raw audio, the mp4) is git-ignored on purpose —
per the assignment, the mp4 goes to the grading website, not GitHub.

## How it works

```
project_proposal.md
        │
        ▼
generate_slide_plan()              LLM: gpt-5.6-luna
  in: proposal text → out: SlidePlan (4-6 slides, structured Pydantic output)
        │
        ├──────────────┬─────────────────────────────┐   (parallel, asyncio.gather)
        ▼               ▼
generate_slide_html()  synthesize()                       LLM: gpt-5.6-luna / TTS: tts-1-hd
  Slide → SlideHTML       draft narration → draft audio
        │               │
        └───────┬───────┘
                ▼
critique_and_revise()              LLM: gpt-5.6-luna, parallel across all slides
  description + narration + visual summary → SlideCritique
  (issues, suggestions, revised_description, revised_narration)
                │
        ┌───────┴───────┐                                (parallel, asyncio.gather)
        ▼               ▼
generate_slide_html()  synthesize()                       LLM: gpt-5.6-luna / TTS: tts-1-hd
  — revised —            — revised —
  → final SlideHTML      → final audio
        │               │
        ▼               │
render_html_to_png()    │                                  Playwright / headless Chromium
        └───────┬───────┘
                ▼
build_reel()                                                ffmpeg — per-slide clip build
  slide_N.png + final audio → reel.mp4                       runs in parallel, then concat
```

See `ai_grading/agent_flow.png` for the rendered version of this diagram
(generated by `agent/flow_diagram.py`).

**Where the parallelization is:** `reel_agent.py` uses `asyncio.gather` at
three points — (1) drafting every slide's HTML *and* its draft narration
audio simultaneously, across all slides at once; (2) critiquing every slide
simultaneously; (3) regenerating every slide's final HTML+PNG *and* its
final narration audio simultaneously, across all slides at once. Each
per-slide clip in the final video is also built in parallel before the
(necessarily sequential) concat step.

### The mandatory "real visual" slide

The slide plan always marks exactly one slide `is_primary_visual=True` with
`visual_type="architecture_diagram_svg"`. Its HTML is required to contain a
real inline `<svg>` diagram (boxes + arrows illustrating the app's
pipeline) — no stock images, no AI-generated images. If the LLM ever
returns that slide without an `<svg>` in it, the code treats that as a
failure and falls back to a procedurally-drawn SVG pipeline diagram instead
of silently shipping a text-only slide (see `agent/slides.py`).

### Running without an API key

Every LLM/TTS call tries the real model first and, only on failure (missing
key, model not served, network blocked), logs a clear warning and falls
back to a deterministic offline provider (`agent/mock_provider.py` for
LLM output, `espeak-ng` for narration). This means `python reel_agent.py`
produces a complete, coherent, on-topic reel even with an empty `.env` —
useful for a first smoke-test, or if `gpt-5.6-luna`/`tts-1-hd` aren't
reachable from your machine. The run log tells you exactly which calls used
which provider, and the final summary line reports how many of the total
calls fell back.

`gpt-5.6-luna` and `tts-1-hd` aren't standard public model IDs; if your
course provides a proxy/gateway that serves them, point `OPENAI_BASE_URL`
in `.env` at it — no code changes needed.

### Optional: Gemini narration

Set `REEL_TTS_PROVIDER=gemini` and `GOOGLE_API_KEY` in `.env` to narrate
with Gemini TTS instead of `tts-1-hd` (per the assignment, this is an
allowed alternative for more expressive voices). It still falls back to
`tts-1-hd`, then to offline `espeak-ng`, if it fails.

## Repository layout

```

requirements.txt
.env.example               — copy to .env; never commit .env (see .gitignore)
project_proposal.md        — the final project proposal this agent reads
reel_agent.py               — main entry point
agent/
  config.py                — paths, model names, provider settings
  models.py                 — Pydantic schemas (SlidePlan, SlideHTML, SlideCritique, ...)
  proposal.py                — loads/parses project_proposal.md
  llm.py                      — gpt-5.6-luna structured calls (+ mock fallback)
  tts.py                       — tts-1-hd / Gemini TTS calls (+ espeak-ng fallback)
  slides.py                     — HTML slide authoring + Playwright PNG rendering
  critique.py                    — the critique-and-revise pass
  video.py                        — ffmpeg clip build + concat
  flow_diagram.py                  — renders ai_grading/agent_flow.png
  mock_provider.py                  — offline fallback content generation
  text_utils.py                      — small text helpers (word-count cap, markdown strip)
slides/                     — final HTML slides (committed)
ai_grading/                 — slide_plan.json, critique_feedback.json, agent_flow.png
build/                      — rendered frames/audio/reel.mp4 (git-ignored)
```

## Costs / timing

With real API calls: 4-6 slides × 2 LLM calls (draft HTML + critique) + 1
plan call ≈ 7-13 `gpt-5.6-luna` calls, and 4-6 slides × 2 TTS calls (draft +
revised narration, each ≤15s of audio) ≈ 8-12 `tts-1-hd` calls per run.
Everything after the LLM/TTS calls (rendering, ffmpeg) is local and free.
A full run (including the offline fallback path, for reference) takes well
under a minute on this machine.
